## In one sentence
A tag is a name/value label you stick on a resource so you can group, filter and bill resources by something that means nothing to Azure but everything to your org — `Environment = Production`, `CostCenter = 00123`.

## Why it exists
Azure gives you resource groups and subscriptions to organise things, but one resource lives in exactly one resource group. Tags cut across that. You want "every VM, disk and database that belongs to the Finance team, wherever it sits" — one tag query answers it, and Cost Management can split the bill by it. Think of them like the asset labels you stick on physical equipment: free-form key/value pairs that drive grouping and reporting, not access.

## Mental model
The trap worth drawing: a tag on a resource group does **not** flow down to the resources inside it. You add tags, or you make Azure Policy add them.

## What actually matters
- **Tags do not inherit.** A resource never picks up its resource group's or subscription's tags. To push a tag down, assign the built-in policy **"Inherit a tag from the resource group"** (a `modify` effect). New/updated resources get it automatically; existing resources need a **remediation task** to backfill.
- **Limits:** max **50** tag name/value pairs per resource, resource group or subscription. Tag **name ≤ 512 chars, value ≤ 256 chars** (storage accounts: name ≤ 128). A handful of services (Automation, DNS zones, CDN, Log Analytics saved searches) cap at **15**. Name can't contain `< > % & \ ? /`.
- **Case:** tag **names are case-insensitive** for operations; tag **values are case-sensitive**.
- **Can't tag management groups.** Resources, resource groups and subscriptions only.
- **Cost:** tags show up in the usage/invoice download and in Cost Management, where you group and filter spend by tag. Tags are **plain text** — never put secrets in them.
- **Replace vs merge:** `az tag create` and `New-AzTag` overwrite all tags. To add without wiping, use the update command with the Merge operation.

## Where it lives
- **Portal (single resource/RG):** resource **Overview > Tags**, or the **Tags** blade > **Add tags** > name/value > **Save**. Bulk: any resource list > tick boxes > **Assign tags**. Find everything with one tag: portal search **"tags"** > pick the tag.
- **CLI** (`az`, v2.10+): `az tag create --resource-id {id} --tags Dept=Finance Status=Normal` (replaces). Add without wiping: `az tag update --resource-id {id} --operation Merge --tags CostCenter=00123`. Also `--operation Replace` / `Delete`; `az tag delete` removes all. Filter: `az resource list --tag CostCenter=00123`.
- **PowerShell** (`Az.Resources` 1.12+): `New-AzTag -ResourceId {id} -Tag @{Dept="Finance"}` (replaces). Add: `Update-AzTag -ResourceId {id} -Tag @{CostCenter="00123"} -Operation Merge` (also `Replace` / `Delete`); `Remove-AzTag` clears all.
- **RBAC:** the **Tag Contributor** role grants tag rights without resource access — but it **cannot** tag resources or resource groups through the **portal** (the portal reads the resource too); it works there only via CLI/PowerShell/REST, and can tag subscriptions in the portal. Plain **Contributor** can tag anything it owns.

## Exam traps
- **"Resources inherit their resource group's tags"** — ==!false==, and the single most tested point. Inheritance only happens if you deploy an Azure Policy with the `modify` effect; existing resources need a remediation task.
- **You cannot tag a management group.** Options offering management-group tags are wrong.
- **`az tag create` / `New-AzTag` replace all tags** — pick them and you wipe existing tags. Merge is the "add one tag" answer.
- **The limit is ==@50 per resource==** (not per subscription-wide, not unlimited). Watch for the 15-tag exception services.
- **Tag names are ==@case-insensitive==, values are ==@case-sensitive==.** `env` and `Env` are the same name; `Prod` and `prod` are different values.
- **Tag Contributor can't tag a resource or resource group in the portal** — a distractor will say it can. It works there via CLI/PowerShell, and for subscriptions in the portal.
