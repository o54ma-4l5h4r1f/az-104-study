## In one sentence
SSPR lets a user who is locked out, expired, or has forgotten their password reset it themselves in a browser, after proving who they are with authentication methods the admin pre-approved.

## Why it exists
Password resets are the single biggest help-desk cost, and a user stuck at a sign-in screen is a user who can't work until someone picks up the phone. SSPR removes the human in the middle.

You already know MFA: prove identity with more than a password. SSPR is the same gate logic pointed at a different door. MFA guards *sign-in*; SSPR guards *resetting the password itself*. The verification methods (Authenticator, SMS, voice, email code) are the ones you know — what is new here is the Entra policy that decides who can self-reset, how many methods they must pass, and what happens in a hybrid tenant.

Note the distinction the exam leans on: **change** vs **reset**. Any signed-in user can *change* their password on any Entra edition. Only SSPR lets a user who *can't sign in* **reset** it, and SSPR needs Entra ID P1 or P2.

## What actually matters
- **Scope is None / Selected / All, and None is the default.** "Selected" requires you to name one security group — a user not in that group cannot self-reset. This is the mechanism for a pilot before going tenant-wide.
- **Methods required to reset = one or two.** The admin enables a set of methods and sets the minimum the user must pass. A user is "registered for SSPR" only once they have set up at least that required number of methods — not after just one, unless one is all you require.
- **Microsoft Authenticator (push and code), software OATH, and hardware OATH count as a single method.** A user cannot satisfy a two-method requirement with push + code from the same app. If you require two and include Authenticator, you must enable at least one more unrelated method.
- **Admin accounts are special, always.** Any account holding an Entra admin role is forced through a strong two-method policy regardless of your settings, and **security questions are never available to admins**. This holds even if you configured one method for everyone else.
- **Password writeback is the hybrid piece.** If a user's password is mastered on-premises (federated, pass-through auth, or password hash sync), SSPR must push the new password *back* to Active Directory. Without writeback enabled, those users get "contact your administrator" and the reset fails. Writeback is deployed through Entra Connect or Entra Connect cloud sync, and needs P1/P2.
- **Registration and reconfirm.** You can force users to register at next sign-in, and set a reconfirm interval of 0–730 days. **0 means never re-ask.** Reconfirm is only available when "require registration" is on.

## Where it lives
**Portal:** Azure portal (or Microsoft Entra admin center) > **Microsoft Entra ID** > **Manage** > **Password reset**. The sub-pages are **Properties** (scope), **Authentication methods** (which methods, how many required), **Registration**, **Notifications**, **Customization**, and **On-premises integration** (writeback).

**Role needed to configure:** **Authentication Policy Administrator**.

**End-user URLs** (worth memorising):
- Register methods: `https://aka.ms/ssprsetup`
- Reset a forgotten password: `https://aka.ms/sspr`

There is no first-class `az` command for the SSPR policy — it is an Entra authentication-methods setting, managed in the portal or via Microsoft Graph (`/policies/authenticationMethodsPolicy` and the authentication-methods policy APIs), not through `az ad`.

## Exam traps
- **Change vs reset.** "A signed-in user updates their password" is a *change* and works on any edition — it is not SSPR and does not need P1/P2. SSPR is specifically the *can't-sign-in* reset. A question that mentions free/Entra ID Free plus self-reset is testing this: SSPR needs ==@P1/P2==.
- **Default is None.** Enabling SSPR is not automatic. If the scenario never set the dial, nobody can self-reset.
- **Authenticator counts once.** The classic distractor: "require two methods, enable only Authenticator push and Authenticator code." That is ==!one method== and users cannot reset. You need a second, unrelated method.
- **Admins are hard-wired to two methods and no security questions.** If a question configures one method for all users and asks what an admin faces, the answer is still two methods. Do not apply the tenant setting to admin accounts.
- **Writeback is the hybrid answer.** "Hybrid users reset in the cloud but the on-prem password doesn't change / reset fails" → the missing piece is password writeback (via Entra Connect or cloud sync). Cloud-only tenants never need writeback.
- **"Registered for SSPR" = registered the required number of methods**, not "registered one method." Watch the wording.
