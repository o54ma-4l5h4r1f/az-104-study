## In one sentence
A license is the entitlement that turns on a paid cloud service (Microsoft 365, EMS, Dynamics 365) for a user, and you assign it either to one user at a time (direct) or to everyone in a group at once (group-based).

## Why it exists
Paid Microsoft cloud services are per-user. Someone has to say "this person gets Exchange, this one doesn't." Direct assignment does that one user at a time and does not scale: when 200 people join a department you are writing a script. Group-based licensing fixes it the way an NSG attached to a subnet fixes per-NIC rules. Attach the license to a group once, and membership drives entitlement. Join the group, get the license. Leave, lose it. No script.

## What actually matters

- **Usage location is a prerequisite.** You cannot assign a license to a user with no **Usage location** set. Some services are blocked by local law. For *group-based* assignment, a user with no usage location inherits the **directory (tenant) location** — set it per user at creation so you do not get surprised.
- **Group-based licensing itself needs a license.** To use it you need **Entra ID P1 (or higher)** or **Office 365 E3 (or higher)**. You also need **at least enough licenses for every unique member** of licensed groups — not a license per group, a license per head.
- **Direct and inherited stack, but a license is consumed once.** A user can get the same product directly and from several groups; it still counts as one consumed license. You cannot remove an *inherited* license from the user page — you change the group membership or the group's assignment.
- **P1 vs P2 is the split that gets tested.** Below.
- **Nested groups are not supported.** Assign to a group of groups and only the first-level members get licensed.

| Tier | What it adds (exam-relevant) |
|---|---|
| Free | Basic user/group management, cloud-user SSPR, basic reports |
| **P1** | Full MFA, **Conditional Access**, self-service group mgmt, password reset **with writeback**, Cloud App Discovery, Entra Connect Health, 99.9% SLA |
| **P2** | Everything in P1 **plus Identity Protection and Privileged Identity Management (PIM)** |

## Where it lives
- **Assign / unassign (both direct and group-based):** Microsoft 365 admin center — `admin.microsoft.com` > **Billing** > **Licenses** > pick a product > **Groups** or **Licensed users** > **Assign licenses**. Group-based licensing is now configured **only** here.
- **View assignments / set usage location:** Microsoft Entra admin center — `entra.microsoft.com` > **Users** or **Groups** > pick one > **Licenses**. The Entra page shows state and has a **Reprocess** button, but sends you to the M365 admin center to change assignments. Usage location: user > **Properties** / **Edit**.
- **PowerShell (Microsoft Graph SDK):** `Set-MgUserLicense` (module `Microsoft.Graph.Users`) and `Set-MgGroupLicense` (module `Microsoft.Graph.Groups`). The old `Set-MsolUserLicense` (MSOnline) is deprecated.
- **Azure CLI:** there is **no `az` command** to assign Entra licenses — use the Microsoft Graph PowerShell SDK or the portal.

## Exam traps
- **Usage location is on the user, not the tenant.** A question that says "set the tenant's usage location to assign licenses" is wrong — you set it per user (group-based falls back to the tenant location only when the user's is blank).
- **P1 vs P2 mix-ups.** MFA and Conditional Access are ==@P1==. ==@PIM== and Identity Protection are ==@P2==. The distractor ==!puts PIM in P1==. Free does **not** include group-based licensing.
- **"Remove the inherited license from the user"** is a trap — you cannot. Remove them from the group, or change the group's assignment.
- **Named error states** map to causes: *CountViolation* = not enough licenses; *MutuallyExclusiveViolation* = conflicting service plans (e.g. E1 direct + E3 via group); *DependencyViolation* = removing a plan another product needs; *ProhibitedInUsageLocationViolation* = unsupported usage location.
- **Group-based errors are silent until reported** — they do not fail loudly like a direct assignment. They are recorded on the user and surfaced in the portal.
- **Moving a user between licensed groups:** add to the destination group **first**, confirm, then remove from the source — otherwise the user is briefly unlicensed.
- **Limits:** assign to a max of **20 groups at a time**; Reprocess handles up to **20 users at a time**.
