## In one sentence
Managing external users means inviting people from outside your tenant to collaborate through Microsoft Entra **B2B collaboration** — they sign in with their own identity, and appear in your directory as a **guest** user object.

## Why it exists
A contractor at `fabrikam.com` needs your SharePoint site. You do not want to create them a new account, set a password, and manage its lifecycle. B2B solves that.

You already understand this. It is **federated trust for individual humans**. The guest authenticates against *their own* home tenant — their password, their MFA, their account lifecycle, none of it yours. Your tenant only holds a lightweight reference object and decides what that object is allowed to touch. Authentication happens over there; authorization happens here. If their employer disables their account, they lose access to your resources automatically, because the credential they used no longer exists.

## Mental model
Two directories, one trust boundary. The person lives in the home tenant. A **stub** of them lives in yours.

## What actually matters

- **Guest vs Member is a user-type flag, not a role.** An invited external user defaults to `userType = Guest`. Guests get restricted directory visibility by default; members see the directory like an employee. You can invite someone as a Member instead, and you can flip the type later. The type controls default directory permissions; it does **not** grant any resource access on its own.
- **The UPN is rewritten.** A guest from `fabrikam.com` lands in your tenant as `john_fabrikam.com#EXT#@yourtenant.onmicrosoft.com`. The `#EXT#` tag is the giveaway that an account is external. Memorise this format.
- **Invitations never expire, and redemption is a one-time consent step.** The guest clicks the redemption link, signs in with their home credential, and consents to your privacy terms. Until then the invite state is **PendingAcceptance**, and you can resend it. (Add your org's privacy statement URL first, or redemption stalls.)
- **Two different settings control two different things.** *External collaboration settings* = which of *your* users may send invitations. *Cross-tenant access settings* = whether B2B with a given external Entra org is allowed at all (inbound/outbound), plus trusting their MFA/device claims. Most restrictive wins when they conflict.
- **Who can invite** has four levels, from "anyone including guests" down to "no one including admins." The **Guest Inviter** role lets a user invite without any broader admin power — it even works when invites are locked to "specific admin roles only."
- **Email one-time passcode (OTP)** is the default fallback when a guest has no Entra or Microsoft account. It is on by default for new tenants.

| Guest user access level | What the guest can see | Default? |
|---|---|---|
| Same access as members | Full directory, like an employee | No |
| Limited access | Own profile + membership of non-hidden groups; can't enumerate users/groups | **Yes** |
| Restricted to own objects | Only their own profile | No |

| Who can invite guests | Who it lets invite |
|---|---|
| Anyone (most inclusive) | All users, including guests and non-admins |
| Member users + specific admin roles | Members and admins (not guests) |
| Only specific admin roles | User Administrator / Guest Inviter only |
| No one (most restrictive) | Nobody, admins included |

## Where it lives

**Portal — invite a guest:** Entra admin center (`entra.microsoft.com`) > **Entra ID** > **Users** > **New user** > **Invite external user**. Fill the **Basics** tab (email + display name), optionally set properties/assignments, then **Review + invite**. Requires at least **Guest Inviter**, **Directory Writers**, or **User Administrator**; assigning Entra roles during invite needs **Privileged Role Administrator**.

**PowerShell** (module `Microsoft.Graph.Identity.SignIns`):

```powershell
Import-Module Microsoft.Graph.Identity.SignIns
$params = @{
  invitedUserEmailAddress = "admin@fabrikam.com"
  inviteRedirectUrl       = "https://myapp.contoso.com"
  sendInvitationMessage   = $true
}
New-MgInvitation -BodyParameter $params
```

Grant invite rights without broader admin power:

```powershell
Import-Module Microsoft.Graph.Identity.DirectoryManagement
$role = Get-MgDirectoryRole | Where-Object {$_.DisplayName -eq "Guest Inviter"}
$body = @{ "@odata.id" = "https://graph.microsoft.com/v1.0/directoryObjects/<userId>" }
New-MgDirectoryRoleMemberByRef -DirectoryRoleId $role.Id -BodyParameter $body
```

**CLI:** there is no dedicated `az ad` command to send a B2B invitation. Use the Graph REST call: `az rest --method post --url https://graph.microsoft.com/v1.0/invitations --body '{"invitedUserEmailAddress":"admin@fabrikam.com","inviteRedirectUrl":"https://myapps.microsoft.com","sendInvitationMessage":true}'`. Know that `New-MgInvitation` is the exam-relevant command, not an `az` one.

## Exam traps

- **Guest vs Member confusion.** ==@Guest== = default for invited externals, restricted directory view. ==@Member== = full directory view. The question will hinge on *default directory visibility*, not on resource permissions — neither type grants resource access by itself.
- **External collaboration settings vs cross-tenant access settings.** This is the classic distractor. "Which users in *my* org can invite" = ==@external collaboration settings==. "Can I collaborate with `contoso.com` at all / trust their MFA" = ==@cross-tenant access settings==. Pick wrong and you lose the mark.
- **Most restrictive wins.** If `adatum.com` is on your blocked-domains list but cross-tenant access allows all orgs, invitations to `adatum.com` are ==!still blocked==. Existing guests keep working after a block; only *new* invites are stopped.
- **Invitations do not expire.** A plausible-wrong answer is "the invite expired, re-create it." ==!Wrong== — resend it; the redemption link stays valid.
- **"Guest Inviter can only invite."** True and testable. It does not let them manage users or read the directory broadly. It is the least-privilege answer when "let this person invite partners but nothing else" is asked.
- **Resetting redemption** (`resetRedemption = true`) re-issues the invite while keeping the same user object ID — used when a guest changes their email. Don't confuse it with deleting and re-inviting.
- **`#EXT#` in the UPN** signals an external account. A question showing a UPN with `#EXT#` is telling you "this is a guest."
