## In one sentence
Three tools that watch and shrink your Azure bill: **Cost Analysis** shows where the money goes, a **budget** fires an alert when spend crosses a threshold, and **Azure Advisor** recommends cheaper configurations.

> **Exam core** — A budget ==!notifies but never caps or stops spending==. A ==@forecasted== alert is the early warning (fires before you cross the line); an ==@actual== alert fires on cost already spent. Credit and department-spend alerts are ==!EA-only==. Advisor judges idle VMs on CPU and outbound network — ==!it ignores RAM/memory==.

## Why it exists
Azure bills you by the hour and never stops a resource because it got expensive. A forgotten VM runs until someone notices the invoice. These tools are the notice. A budget is a watch-and-warn pipeline on spend: a threshold trips, an alert fires to an action group — the *same* action-group plumbing you meet again in Azure Monitor (D5.1.4). Think of it as a logging alert rule, but the metric is dollars. The one thing it is **not** is a quota. A budget ==!does not cap, throttle, or shut anything down==. Consumption continues; you just get an email.

## Mental model
A budget has three parts: a **scope + reset period**, one or more **thresholds** (actual or forecasted % of the amount), and **who gets told** (emails plus an optional action group).

## What actually matters

**A budget notifies, it never caps.** Resources keep running and consumption is not stopped. The alerting is also ==!not instant== — three delays matter:

| Timing fact | Value |
|---|---|
| Does a budget cap or stop spend? | ==!No — notify only== |
| Budget evaluation cycle | ~every **24 hours** |
| Cost/usage data latency | **8–24 hours** behind real time |
| Brand-new subscription before Cost Management works | up to **48 hours** |

The three cost tools are easy to confuse. What each *is*, *does*, and where it reaches:

| | Budget | Cost alerts (credit / dept quota) | Advisor cost |
|---|---|---|---|
| What it is | a spend threshold **you** set | **automatic** alerts Azure raises | a configuration-recommendation engine |
| What it does | notifies at actual/forecasted % — ==!never caps== | credit fires at 90% & 100%; dept quota at set % | suggests shutdown / resize / burstable / reserved |
| Scope | MG, subscription, RG + EA/MCA billing scopes | ==!EA only== | subscription, resource group |

- **Scope and reset period define a budget.** Scopes: management group, subscription, or resource group (Azure RBAC), plus EA scopes (billing account, department, enrollment account) and MCA scopes (billing profile, invoice section). Reset period is ==@monthly, quarterly, or annually== — quarterly/annual amounts are split evenly across the months.
- **A budget maintains itself.** Cost resets to zero at the start of each period, the budget **resets automatically** for the same amount, and it is **deleted automatically** when it expires.
- **Thresholds are actual vs forecasted.** You need at least one threshold (% of budget) and one email; you can set up to **five** of each. The valid range is ==@0.01% to 1000%==. An ==@actual== alert fires on cost already accrued; a ==@forecasted== alert fires when the projection says you will cross the line — the early warning. In the Azure portal budgets are defined by cost; via the Consumption API they can be cost- or usage-based.
- **Action groups attach only at subscription and resource-group scope** — ==!not management-group scope==. The action group can email, push to the Azure mobile app, or trigger automation (Function, Logic App, webhook). Note: a budget created with ==!PowerShell does not send notifications==; use the portal or REST API for alerting.

![Budget with spending shown in cost analysis](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/media/tutorial-acm-create-budgets/cost-analysis.png){A budget appears as a line against your spend in Cost Analysis}

![Budgets shown in the Azure mobile app](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/media/tutorial-acm-create-budgets/azure-app-budgets.png){Budgets in the Azure mobile app — subscription and resource group scopes only}

- **Budget alert ≠ metric alert.** A budget alert lives in Cost Management and compares actual or forecasted ==@spend (money)== to your amount, checked daily. A metric alert (D5.1.4) lives in ==@Azure Monitor== and fires on a **resource metric** (CPU %, disk IOPS) in near real time. If the question is about dollars, it is a budget; if it is about resource telemetry, it is Azure Monitor.
- **Azure Advisor cost recommendations** cover: **shut down idle VMs/scale sets** (7-day lookback, judged on CPU and outbound network — ==!not memory==), **right-size/resize** to a cheaper SKU, move to a **burstable (B-series) SKU**, and **buy reserved instances / savings plans**. Estimated savings use ==@retail rates== and ignore any existing reservations or discounts, so they can read higher than reality.

![Azure Advisor configuration for VM and scale set right sizing](https://learn.microsoft.com/en-us/azure/advisor/media/advisor-get-started/advisor-configure-rules.png){Advisor Configuration > VM/Virtual Machine Scale Sets right sizing — set a CPU filter per subscription}

- **Tag-based cost allocation** works by grouping and filtering Cost Analysis — and budget filters — by a resource ==@tag== (for example `costCenter` or `environment`). It only works if resources are actually tagged (see D1.3.3); untagged spend lands in a separate bucket.

- **Advisor:** Azure portal > **Advisor** > **Cost** tab. Tune right-sizing with **Advisor > Configuration > VM/Virtual Machine Scale Sets right sizing**.

- **PowerShell (Az.Consumption / Az.Advisor):** `New-AzConsumptionBudget -Category Cost -TimeGrain Monthly -NotificationThreshold 0.9` · `Get-AzAdvisorRecommendation -Category Cost`. (MCA customers must use the Budgets REST API.)

## Exam traps
- **"Budget stops the resource / prevents the spend" is always wrong.** It ==!sends a notification==. Nothing is throttled or deleted. A distractor will offer "resources are deallocated at 100%" — ==!no==.
- **Forecasted vs actual.** "Warn me *before* I exceed" = ==+forecasted== alert. "Tell me when I've already spent X" = ==+actual==. Mixing these is the classic trick.
- **Credit and department-quota alerts are ==!EA-only==.** On a pay-as-you-go or MCA subscription, the only cost alert available is the ==+budget== alert. Don't pick credit/quota for PAYG.
- **Credit alerts are automatic at ==@90% and 100%==** — you do not configure the thresholds. Department quota alerts are on fixed percentages too. Only *budget* thresholds are user-defined.
- **Action groups are ==!not available at management-group scope==.** If the scenario needs a budget to trigger an Azure Function at MG level, that is not supported — subscription or resource group only.
- **Budget alert vs Azure Monitor metric alert.** Spend in dollars = Cost Management budget. CPU/disk/network telemetry = Azure Monitor. They are different systems with different scopes.
- **Advisor shutdown logic ==!ignores memory==.** It judges idle VMs on CPU and outbound network over 7 days. "Advisor recommended shutdown because RAM was low" is ==!false==.
- **Advisor savings are retail-rate estimates** and ignore existing reserved instances — acting on a right-size recommendation can occasionally ==!raise cost== if you hold reservations.
