# D1 — Manage identities and governance

*Weight 20–25%. Review this last. Print it: Ctrl/Cmd + P. Every number here is grounded in the D1 objective pages.*

## Entra users & groups (D1.1.1–1.1.2, 1.1.4)

- **Three independent axes** — never conflate: user **type** (`Member`/`Guest`), group **membership** (`Assigned`/`Dynamic`), user **source** (cloud / synced / invited). A question mixing them is testing exactly this.
- **Source decides where you edit.** Cloud + guest → edit in Entra. ==!Synced user identity fields are read-only in Entra== — change on-prem, wait for sync.
- **Deleted users** soft-delete **30 days**, then auto-purge permanently.
- **Dynamic membership** rule is `user.property -operator "value"` (e.g. `user.department -eq "Sales"`); builder = ≤5 expressions, user groups only. Needs ==@Entra ID P1==.
- **Nesting:** only **Security** groups nest. Nested members do ==!not inherit== the parent's app/resource access or licenses. Can't nest a security group inside a Microsoft 365 group.
- **Guest = B2B:** invite by *their own email* (not `guest@yourdomain`). Guest authenticates against **their** home tenant; your tenant holds a lightweight stub. Employer disables them → access gone automatically.

## Licensing (D1.1.3)

| | Detail |
|---|---|
| Two models | **Direct** assignment vs **group-based** (assign licence to a security group) |
| Group-based in Free? | ==!No== — needs a paid tier |
| Inherited licence | Can't be removed directly from the user; remove from the group |
| **P1** | MFA, Conditional Access, group-based licensing, password writeback, dynamic groups |
| **P2** | ==@PIM==, Identity Protection. Distractor ==!puts PIM in P1== |

## SSPR (D1.1.5)

- **Change vs reset** — the hinge. *Change* (signed-in user updates password) works on **any edition**, is **not** SSPR. *Reset* (can't sign in) **is** SSPR and needs ==@P1/P2==.
- Scope dial: **None** (default) / **Selected** (one group) / **All**. Default None → nobody self-resets unless set.
- **Methods required = 1 or 2.** "Registered for SSPR" = registered the **required number** of methods, not one.
- **Hybrid:** password **writeback** (Entra Connect / cloud sync) must be on, or on-prem-mastered users get "contact your administrator".

## RBAC (D1.2)

- **Four scope levels, inherit DOWN only:** Management group → Subscription → Resource group → Resource. Never up or sideways. Child owner ==!can't opt out== of a higher assignment.
- **Allow is additive; deny wins.** Effective access = union of all role assignments, **minus** any **deny assignment**. Deny assignment overrides allow. (Azure **Policy Deny** is a separate gate — see governance.)
- **Built-in roles** have `AssignableScopes = "/"` → assignable at any scope. Custom roles list their own scopes. Tenant cap: **5,000 custom roles**.
- **Role assigned to a group** reaches every member, including nested-group members (transitive).

### The four roles people confuse

| Role | Can do | Can assign roles? |
|---|---|---|
| ==@Owner== | everything + manage access | ✅ |
| ==@Contributor== | manage resources | ==!❌ No== (classic trap) |
| ==@User Access Administrator== | **access only** — nothing to resources | ✅ (incl. deny assignments) |
| ==@Role Based Access Control Administrator== | role assignments only | ✅ assignments, ==!❌ not deny assignments== |
| ==@Reader== | view only | ❌ |

## Governance (D1.3)

**Azure Policy (D1.3.1)** — governs *resource properties*, not identity. Effects: `Deny`, `Audit`, `Append`, `Modify`, `DeployIfNotExists`, `Disabled`. `Modify` / `DeployIfNotExists` need a **managed identity + remediation task** to fix existing resources. Policy vs RBAC: RBAC = *who can act*; Policy = *what the resource may look like*.

**Resource locks (D1.3.2)** — `CanNotDelete` and `ReadOnly`. Inherit down; **most-restrictive wins** (parent ReadOnly + child CanNotDelete → child is effectively ReadOnly). ==!Neither protects data== (blob contents, disk/VM data). Delete lock on one resource blocks deleting its whole RG.

**Tags (D1.3.3)** — ==!Tags do NOT inherit== (most-tested point). Push down with built-in policy **"Inherit a tag from the resource group"** (`modify` effect); existing resources need a **remediation task**. Limits: **50** pairs; name ≤512, value ≤256 chars; some services cap at 15.

**Resource groups (D1.3.4)** — a resource lives in **exactly one** RG. RGs ==!can't nest, can't be renamed==; deleting the RG deletes everything in it.

**Subscriptions (D1.3.5)** — billing + access + scale boundary. **Creating** one needs a **billing role**, not just Azure RBAC. Cross-tenant creation = a **request**, expires in ==@7 days==. ==!Moving a subscription to another directory DELETES all role assignments and custom roles== (classic trap). Directory transfer ≠ billing-ownership transfer.

**Management groups (D1.3.7)** — scope **above** subscriptions, inherit down.

| | |
|---|---|
| Per directory | ==@10,000== |
| Depth | ==@6 levels== (root + subscription levels don't count) |
| Parents each | exactly **one** |
| Root | "Tenant root group", ID = tenant ID, can't move/delete; new subs land here |
| Root access | ==!Nobody, not even Global Admin, has default access== — GA must **elevate** to User Access Admin at tenant scope first. ARM caches ~30 min |

**Cost (D1.3.6)** — **Budget** = spend threshold that fires **alerts** (doesn't stop spend). **Cost alerts** notify; **Advisor** recommends savings. A budget alerting ≠ a hard cap.

## Permissions — who can do what (cross-cutting)

| Action | Role / right required |
|---|---|
| Create users | ==@User Administrator== |
| Invite guests (B2B) | ==@Guest Inviter== |
| Create / manage groups | ==@Groups Administrator== or User Administrator |
| Manage custom security attributes | Attribute Definition Admin (define) + Attribute Assignment Admin (set) — ==!not User Admin, not GA by default== |
| Tenant-wide user settings (app reg, guest limits) | ==@Global Administrator== |
| Assign a role (RBAC) | Owner, User Access Administrator, or RBAC Administrator — ==!never Contributor== |
| Create a **deny** assignment | User Access Administrator (==!not RBAC Administrator==) |
| Create / delete resource locks | Owner or User Access Administrator (`Microsoft.Authorization/locks/*`) |
| Manage the **root** management group | GA **elevates** to UAA at tenant scope, then assigns |
| Create a subscription | a **billing** role (invoice section / billing profile / account) — Azure RBAC alone is not enough |
| Azure access for a Global Admin | ==!None automatic== — Entra ≠ Azure RBAC; GA must elevate access |

## Top traps → truth

- "Contributor can assign roles" → ==!No.== Owner / UAA / RBAC Admin only.
- "User Access Admin can manage resources" → ==!No.== Access only.
- "Global Admin owns Azure subscriptions / the root MG" → ==!No.== Must elevate.
- "Resources inherit the RG's tags" → ==!No.== Policy `modify` + remediation.
- "Role assignments move with a transferred subscription" → ==!No.== Deleted; rebuild.
- "A locked resource's data is protected" → ==!No.== Locks stop management ops, not data.
- "PIM is P1" → ==!No.== PIM/Identity Protection = **P2**.
- "A signed-in password change is SSPR" → ==!No.== That's a *change*; SSPR = *reset* (P1/P2).
